# Board access

Board accounts can inspect tab after the competitive inround phase is mostly over,
audit recorded corrections, and repair outround data for results reporting.

## Access timing

Access opens when an outround has been created, or at least 80% of debates in the
configured final inround have an entered outcome. This is a chronological proxy;
missing speaks, ranks or written RFDs do not delay board access. Simply pairing
the final inround does not open access. The gate applies to authentication and
every active board request. If it closes again, the active session receives a
neutral denial rather than a redirect exposing tournament details.

## Allowed work

- Read historical inround teams, judges, chairs, rooms, outcomes, and recorded
  manual changes. Inround pairings and results cannot be changed by board.
- Read tab cards and forum-post results independently of public publication.
- Change only `is_dino` on judges; the general judge editor remains inaccessible.
- Create the initial team break if no bracket exists, and pair subsequent
  varsity/novice outrounds using teams and rooms only.
- Correct outround outcomes, including clearing an incomplete result; switch
  sides while preserving the winning team's identity; replace or swap teams;
  assign rooms; and correct choice.
- Continue APDA ID import/export and standings-publication workflows. APDA ID
  spreadsheets accept and export CSV, XLS, and XLSX using only school/debater
  names and APDA IDs. Extra input columns cannot update other fields; invalid ID
  values abort all updates in that file. Roster exports (including judges and
  scratches) remain inaccessible to board accounts, even with superuser access.

Switching teams between two matches swaps the participants and clears both
affected outcomes. Team replacement clears that match's outcome. All existing
judge assignments and chairs are preserved. Outcome reversals recompute effective
seeds from original break seeds and the current outcomes. Corrections that leave
previously eliminated or duplicate teams in later rounds display a warning;
advancing an inconsistent bracket is blocked until its teams/results are fixed.
Existing rounds are never deleted or regenerated by board commands.

Room choices are the room roster, without judge compatibility filtering. Automatic
assignment uses checked-in unoccupied rooms alphabetically and never calls judge
pairing or eligibility helpers. Panel assignment and compatibility review remain
staff work. A room already used by another undecided outround cannot be assigned
to an undecided match.

Board writes require POST and CSRF. Outround forms include a revision fingerprint
of permitted pairing state so stale forms cannot overwrite newer corrections.
Writes and their audit records are atomic; board corrections serialize on the
tournament settings row and recheck access within the transaction.

## Confidentiality boundary

Already-public judge identities/assignments/chair roles are allowed. Board access
must not add scratch records, scratch counts or change history, judge candidate
lists, conflict explanations, calibration values, wing-only flags, or ordering
derived from judge calibration. Speaker ranks on ballots are allowed and are
distinct from judge calibration.

The server uses an explicit named-route/method allowlist. Board membership wins
over staff groups and superuser flags. Team and judge-code portals, Django admin,
backups and backup metadata, scratch-free backups, raw XML/JSON exports, scratch
tools, broad settings and staff management remain denied. The existing Black Rod
bundle remains allowed because it explicitly serializes safe results and public
judge identities/roles without access codes, scratches or calibration.

Dedicated board contexts contain explicit dictionaries. Raw audit notes,
unrestricted Judge or AuditEvent objects, protected changed-field lists and
written RFDs are not rendered. Judge names are alphabetically ordered. Public
response caches are bypassed for board requests, board responses are private and
not cacheable, and debug exception details are replaced with a neutral error.

## Audit evidence

Existing structured manual judge assignment/removal/chair records are visible
through a safe field projection. New pairing/result changes add before/after
snapshots with actor, timestamp and operation source. The board audit displays
only manual corrections: board corrections, staff
team/room/side/choice/result corrections, structured judge/chair edits, and
Round/Outround/RoundStats admin edits. Automatic pairing, re-pairing, bulk
judge/room assignment, initial breaks, and routine ballot/panel entry are excluded
by an explicit operation allowlist, including previously recorded events. Removed
pairings appear only for manual deletion, never automatic re-pairing.
Protected fields and arbitrary notes are never part of the board projection.

Historical actions that were not recorded cannot be reconstructed. The application
audit table is not an independently held tamper-proof record: an operator with
database access or a full database restore can rewrite history. Board accounts
have no route to modify history or perform restores. Independent custody of audit
events would be a separate infrastructure project.

Board inround cards share the staff pairing card layout and round navigation,
with read-only teams, alphabetical public judges/chairs, outcomes and rooms.
Manual history is visible inline; no accordion is required. Manual team/side
changes and current manual judge/chair changes use the same yellow styling as
staff cards. Staff inround and outround team highlights persist on reload; judge
re-pairing does not clear team highlights.

Staff pairing cards show manual judge edits since the latest successful automatic
judge assignment for that debate. Re-pairing clears those card annotations even
when the panel stays the same. Earlier edits remain in the full audit history,
including the board's safe projection. Failed judge assignment leaves the existing
panel and card annotations intact; scoped outround assignment resets only the
selected undecided debates.

## Verification

`mittab/libs/tests/views/test_board_audit_access.py` tests access timing, active
sessions, extra privilege flags, direct protected-route requests, response
projection, independence from scratch/calibration changes, prohibited database
reads, read-only inrounds, protected-state preservation, judge-logic isolation,
bracket/seed correctness, stale forms, CSRF and transaction rollback.

Run this suite together with the existing board, tab, export, public-view and
outround tests. The required lint commands remain those in AGENTS.md. Core feature
changes require no dependency updates or database migration.

The security suite has been exercised on isolated SQLite and MySQL 8.0.43,
including direct-access attempts with additional staff and superuser privileges.
External backup subprocesses were stubbed during these local runs to avoid
contacting another tournament database. No dependency versions were changed.
